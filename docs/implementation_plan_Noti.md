# خطة العمل المتكاملة والبرومبت: تفعيل وتطوير منظومة الإشعارات الذكية في نظام FuelTrack

## 📋 نظرة عامة على الوضع الحالي والهدف
تم فحص الكود الحالي للواجهات الأمامية والخلفية، ووجدنا الآتي:
1. **قاعدة البيانات ونموذج البيانات**: تتوفر جداول `Notifications` و `NotificationRecipients` و `InstalledParts` و `Oils` و `FuelTanks`.
2. **الخدمات الخلفية (Backend)**:
   - خدمة `NotificationService` تطبق تصفية نطاق البيانات `IUserScopeFilterService` بحسب المحطات الفرعية.
   - وظيفة `FuelStockAlertJob` ترسل بريداً إلكترونياً فقط عند نقص الوقود، لكنها **لا تُنشئ إشعارات داخل النظام (In-App)** ولا تغطي الزيوت أو قطع الغيار.
   - يوجد تفاوت بين بنية استجابة `GET /api/notifications` وما تتوقعه الواجهة الأمامية (`List<NotificationDto>` مقابل `{ notifications: [...], unreadCount: N }`).
3. **الواجهة الأمامية (Frontend)**:
   - صفحة `Notifications.jsx` مجهزة بتصميم وتصنيفات لأنواع الإشعارات ولكن بحاجة لربط كامل، وتحديث عداد الجرس في الهيدر، ودعم SignalR اللحظي أو التحديث التلقائي.

## 🎯 نطاق الإشعارات المطلوب تفعيلها

1. **إشعارات انخفاض مخزون الوقود (Low Fuel Tank Alert)**:
   - عند وصول الرصيد الفعلي للخزان `ActualStockLiters` إلى مستوى التنبيه `MinAlertLiters` أو أقل.
2. **إشعارات انخفاض مخزون الزيوت (Low Oil Stock Alert)**:
   - عند وصول رصيد الزيت `CurrentStock` إلى الحد الأدنى `MinStock` أو أقل بالمحطة/المحطة الفرعية.
3. **إشعارات قطع الغيار ومواعيد الاستبدال (Spare Parts Maintenance Alert)**:
   - لقطع الغيار المركبة `InstalledParts` على المولدات النشطة:
   - تنبيه استباقي: عند اقتراب ساعات التشغيل `OperatingHours` من موعد التبديل المقدر `EstimatedReplacementAtHours` (مثلاً: تبقى أقل من 50 ساعة أو 10%).
   - تنبيه عاجل: عند تجاوز موعد التبديل المقدر (`OperatingHours >= EstimatedReplacementAtHours`).
4. **إشعارات تدفق العمليات (Workflow Notifications)**:
   - إشعار عند إرسال قراءات بانتظار الاعتماد (`reading_pending`).
   - إشعار عند رفض أو اعتماد قراءة يومية / جرد وقود وزيوت.
   - إشعار عند طلب توريد أو إذن عمل صيانة (`work_permit_assigned`).

## 🔐 آلية الصلاحيات ونطاق البيانات (Data Scope & RBAC)

- **حسب الصلاحيات (Permissions)**:
  - إشعارات الوقود والزيوت: للمستخدمين الحاصلين على صلاحية إدارة الوقود/الزيوت أو العرض.
  - إشعارات قطع الغيار والصيانة: لمهندسي وفنيي الصيانة ومدراء المحطات.
  - إشعارات الاعتمادات: للمشرفين والمدراء المعتمدين.
- **حسب نطاق البيانات (Data Scope)**:
  - استخدام `IUserScopeFilterService.GetUserIdsWithAccessToSubStationAsync(subStationId)` لتحديد مستلمي الإشعار بدقة، بحيث لا يرى المستخدم إلا تنبيهات الفروع والمحطات التابعة لنطاقه.
  - يرى مدير النظام `SystemOwner` و `Admin` كافة الإشعارات العامة.

## 🛠️ مراحل التنفيذ التقنية (Implementation Steps)

### المرحلة 1: تطوير خدمات وخلفية الإشعارات (Backend Enhancements)
- [ ] توحيد DTOs في `NotificationsController` لترجع `{ notifications: NotificationDto[], unreadCount: int }`.
- [ ] إنشاء خدمة تنبيهات ذكية `IAlertGeneratorService` و `AlertGeneratorService`:
  - `CheckFuelStockLevelsAsync()`: فحص خزانات الوقود وتوليد إشعارات `fuel_low`.
  - `CheckOilStockLevelsAsync()`: فحص مخزون الزيوت وتوليد إشعارات `oil_low`.
  - `CheckInstalledPartsReplacementAsync()`: فحص ساعات عمل المولدات ومقارنتها بقطع الغيار المركبة وتوليد إشعارات `part_replacement_due` و `part_replacement_overdue`.
- [ ] ربط المهام المجدولة (Hangfire Jobs):
  - تحديث `FuelStockAlertJob` لحفظ إشعارات داخلية وإرسال تنبيه SignalR.
  - إضافة `OilStockAlertJob` و `SparePartReplacementAlertJob`.

### المرحلة 2: البث اللحظي وتكامل SignalR (Realtime Notifications)
- [ ] تفعيل إرسال الإشعارات عبر SignalR `RealtimeNotifier` إلى مجموعات المحطات أو المستخدمين المحددين فور وقوع الحدث.
- [ ] دعم WebSocket/SignalR في الواجهة مع Fallback مجدول.

### المرحلة 3: الواجهة الأمامية والهيدر وتجربة المستخدم (Frontend & UI)
- [ ] إضافة زر/أيقونة جرس الإشعارات مع شارة العداد الحي (Unread Badge) في الهيدر / السايدبار.
- [ ] قائمة منسدلة سريعة (Notification Dropdown) لعرض آخر 5 تنبيهات مع إمكانية التعليم كمقروء مباشرة.
- [ ] تحديث صفحة `Notifications.jsx` لدعم أنواع التنبيهات الجديدة (قطع غيار، زيوت، وقود) مع روابط مباشرة للانتقال للكيان المعني (مثلاً: الانتقال للمولد أو الخزان المعني بضغطة زر).

### المرحلة 4: الاختبار والتحقق (Testing & Verification)
- [ ] كتابة اختبارات وحدة (Unit Tests) لـ `AlertGeneratorService` و `NotificationService`.
- [ ] اختبار محاكاة وصول خزان وقود ومخزون زيت لحده الأدنى وساعات تشغيل مولد لموعد استبدال فلتر/قطعة غيار.
- [ ] التحقق من ظهور الإشعارات بحسب نطاق المستخدم (`UserScope`).
